# Удалённые хосты для Omarchy

[English version](README.md)

Плагин для панели Omarchy, объединяющий каталог удалённых хостов, SSH, SFTP,
VS Code Remote-SSH, строгую проверку host key и запуск интерактивных AI CLI в
нативной панели QML/Quickshell.

Идентификатор плагина: `vornashev.remote-hosts`

## Возможности

- Каталог с группами, закреплением, заметками, проверкой доступности и лимитом 100 хостов.
- Две раскладки одной панели: узкая — список и панель действий снизу, широкая —
  список и подробности хоста справа. **Авто** включает широкую, если на экране
  для панели остаётся не меньше 760 px.
- Поиск по имени, адресу, группе и заметке; Enter подключает к лучшему совпадению.
- Задержка окрашивается только цветами темы: нейтральный до 50 мс, акцентный
  от 51 до 99 мс, urgent от 100 мс. Статусы обновляются по хостам с полосой прогресса.
- SSH в Ghostty, Kitty, Alacritty или foot.
- SFTP через SSHFS с открытием в Nautilus.
- Изолированные профили VS Code Remote-SSH без изменения `~/.ssh/config`.
- Выбор AI CLI и необязательной рабочей папки для каждого хоста.
- Сохранение скриптов для каждого хоста и запуск в терминале по явному нажатию.
- Импорт и экспорт JSON без паролей и признаков наличия сохранённого секрета.
  Предпросмотр импорта показывает каждый входящий хост как новый, обновлённый
  или пропущенный; экспорт показывает образец файла для выбранных опций.
  Закрепление не экспортируется, а импорт с заменой сохраняет локальное.
- Хранение серверных паролей и выбранных парольных фраз SSH-ключей только через Secret Service.
- Английский интерфейс по умолчанию; русский выбирается в общих настройках.

Поддерживаемые интерактивные AI CLI:

| Агент | Команда на сервере |
| --- | --- |
| Pi | `pi` |
| Codex | `codex` |
| Claude | `claude` |
| OpenCode | `opencode` |
| Gemini CLI | `gemini` |
| Aider | `aider` |
| Goose | `goose session` |
| Amp | `amp` |
| GitHub Copilot CLI | `copilot` |
| Qwen Code | `qwen` |

Команды и аргумент `session` для Goose зафиксированы в backend. Плагин не
принимает произвольные executable, аргументы, shell-фрагменты или флаги
автоматического разрешения действий для запуска AI CLI. Пользовательские
скрипты — отдельная функция удалённого выполнения: проверяйте их перед запуском.

## Панель и клавиатура

При открытии фокус стоит в поле поиска, а выбранный ранее хост восстанавливается.
Хост выбирается щелчком или ↑↓; панель действий (узкая раскладка) или подробности
(широкая) следуют за выбором. Наведение мыши и курсор клавиатуры подсвечиваются
одинаково.

| Клавиша | Действие |
| --- | --- |
| `/` | Перейти к поиску |
| ↑ ↓ | Переместить выбор |
| Tab | Следующая вкладка группы (узкая) или переход между списком и подробностями (широкая) |
| Enter | SSH к выбранному хосту или лучшему совпадению поиска |
| Пробел / `P` | Закрепить или открепить |
| `F` / `C` / `Y` | Файлы (SFTP), VS Code, копировать SSH-адрес |
| `A` / `S` | Выбор AI CLI или скрипта; `1`–`9` запускают из списка |
| `E` / `K` / `R` / Del | Изменить, проверить ключ хоста, повторить проверку, удалить |
| Ctrl+Enter | Сохранить форму хоста |
| Esc | Закрыть выбор или подтверждение, очистить поиск, затем закрыть панель |

Правый щелчок по хосту открывает контекстное меню, двойной — подключает.
Удаление хоста и пустой группы подтверждается прямо на месте. Если для запуска
нужен ключ хоста, появляется уведомление с действием **Проверить** (`K`),
которое открывает сверку fingerprint; после подтверждения запуск продолжается.
Закрепление сохраняется в профиле, а вкладки групп, свёрнутые группы и выбор —
только состояние вида.

## Скрипты хоста

Выберите хост и нажмите **Добавить скрипт** в списке его скриптов, чтобы ввести текст или выбрать
локальный исполняемый `.sh` в домашнем каталоге. Файл должен принадлежать вам,
не быть symlink, содержать UTF-8, быть не больше 16 КиБ и не разрешать запись
другим пользователям. Плагин сохраняет приватную **копию** в `scripts.json`
(0600); изменение исходного файла не меняет сохранённый скрипт. Общий лимит —
32 скрипта. Скрипты остаются на этой машине и не входят в импорт/экспорт хостов.
Окно выбора файлов запоминает последний успешно открытый каталог после
перезапуска shell в приватном `script-browser.json` (0600). Если каталог
исчез, откроется домашняя папка. Этот путь не экспортируется.
В ответах списка для каждого скрипта передаётся только первая командная строка
(без shebang и комментариев, не длиннее 120 символов) как однострочный
предпросмотр; полное содержимое не возвращается. При открытии
редактора сохранённая копия загружается по локальному каналу предпросмотра.
У скриптов из файлов поле содержимого доступно только для чтения, а путь
исходного файла сохраняется. Выбор другого `.sh` заменяет сохранённую копию;
переименование не перечитывает исходный файл. У ранее сохранённых скриптов
содержимое видно, но исходный путь восстановить невозможно. Скрипты, введённые
вручную, остаются редактируемыми. Изменение адреса, порта либо логина хоста
блокирует старые скрипты; удаление хоста удаляет их.

Нажатие на скрипт (или выбор через `S` и номер) открывает терминал и выполняет его на хосте через SSH с `sh -s`
или `bash -s` по поддерживаемому shebang (`#!/bin/sh`, `#!/usr/bin/env sh`,
`#!/bin/bash`, `#!/usr/bin/env bash`).
Текст передаётся по stdin, а не в аргументах командной строки или переменных
окружения. Требуются проверенный host key и строгая проверка ключа. Это
намеренный запуск пользовательского кода на сервере: не включайте пароли,
токены или приватные ключи. Скрипт не остаётся файлом на удалённом хосте.
Терминал показывает результат; при закрытии или потере соединения выполнение
может прерваться.

## Зависимости

- Omarchy Shell / Quickshell.
- Python 3, только стандартная библиотека.
- OpenSSH: `ssh`, `ssh-keyscan` и `ssh-keygen`.
- Один из поддерживаемых терминалов.
- Необязательно: `secret-tool` и разблокируемый Secret Service для паролей или сохраняемых парольных фраз ключей.
- Необязательно: `sshfs`, FUSE 3 и Nautilus для SFTP.
- Необязательно: VS Code с официальным расширением `ms-vscode-remote.remote-ssh`.
- Необязательно: `wl-copy` для копирования SSH-адресов. Копируется `логин@хост`, для нестандартного порта добавляется ` -p порт`.

AI CLI должны быть заранее установлены и авторизованы в `PATH` login shell
удалённого пользователя. Плагин не устанавливает программы на сервер.

## Установка

```bash
git clone https://github.com/vornashev/omarchy-remote-hosts.git
cd omarchy-remote-hosts

PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest discover -s tests
omarchy plugin validate "$PWD"
scripts/qml-lint
scripts/deploy-local

omarchy plugin enable vornashev.remote-hosts
# Необязательно:
omarchy bar move vornashev.remote-hosts --section right
```

`scripts/deploy-local` валидирует исходники, копирует их в
`~/.config/omarchy/plugins/vornashev.remote-hosts`, устанавливает executable bit для
askpass и обновляет реестр плагинов. Скрипт не устанавливает пакеты и не меняет
`~/.ssh/config`.

## Иконка в баре

Иконка занимает прежний слот 27 px и показывает один сигнал за раз, по
приоритету: закреплённый хост недоступен (красный бейдж), идёт проверка
(иконка приглушена, нижняя плашка пульсирует), смонтирован SFTP (нижняя плашка
тусклее), включено скрытие адресов (сплошные плашки), иначе — обычная иконка.

| Ввод | Действие |
| --- | --- |
| ЛКМ | Открыть или закрыть панель |
| СКМ | Проверить все хосты (ping и SSH-порт) |
| ПКМ | Быстрое меню: до пяти закреплённых хостов (подключение по SSH), проверить все, отключить смонтированные SFTP, скрыть или показать адреса, открыть панель |
| Наведение | Сводка: число хостов и закреплённых, недоступные закреплённые, активные SFTP, время проверки |
| Колесо | Листать закреплённые хосты в подсказке; прокрутка ничего не запускает |

Подсказка и быстрое меню показывают только имена хостов, без `user@host`.
Подключение из меню идёт тем же путём, что и из панели: строгая проверка
ключа хоста и askpass; если запуск не удался или нужен ключ хоста, открывается
панель с уведомлением. Escape или щелчок мимо закрывают меню.

Каталог читается из локальных файлов при запуске оболочки, поэтому иконка и
подсказка работают до первого открытия панели; к хостам никто не обращается до
проверки. **Настройки → Проверять закреплённые** по желанию перепроверяет
закреплённые хосты каждые 5, 15, 30 или 60 минут (по умолчанию выключено).

## Язык и терминал

Откройте каталог и выберите **Settings / Настройки**:

- **Language / Язык:** English или Русский. Для новой установки выбран English.
- **Panel layout / Раскладка панели:** Авто, Компактная (узкая) или Широкая.
- **Check pinned hosts / Проверять закреплённые:** Выкл. или фоновая проверка раз в 5–60 минут.
- **Default terminal / Терминал по умолчанию:** Ghostty, Kitty, Alacritty или foot.

Терминал используется новыми окнами SSH и AI CLI для всех хостов. Недоступный
терминал сохранить нельзя; автоматического fallback нет. VS Code и SFTP остаются
отдельными действиями. Язык, раскладка, фоновая проверка и терминал локальны для машины,
применяются после **Сохранить** и не входят в импорт или экспорт профилей.

## Секреты аутентификации

Для профиля с паролем серверный пароль хранится в Secret Service. Для профиля
«Ключ / SSH-агент» можно указать абсолютный путь к приватному ключу и включить
**Сохранять парольную фразу ключа**. Фраза хранится в отдельном namespace Secret
Service; в профиль попадают только флаг настройки и путь к ключу.

При первом сохранении, включении опции или смене адреса, порта, логина либо пути
к ключу фразу нужно ввести заново. Пустое поле сохраняет прежнюю фразу только
при неизменной привязке. Выключение опции или удаление хоста очищает
соответствующую фразу после безопасной публикации изменения профиля.

Сохранённая фраза передаётся только SSH в терминале, SSH для AI CLI и SFTP.
VS Code Remote-SSH использует собственный запрос и обработку фразы. При
экспорте флаг всегда сбрасывается; новые импортированные хосты получают
выключенную опцию, а replace-импорт сохраняет локальные способ входа, путь к
ключу и флаг.

## Приватность при демонстрации экрана

Кнопка-глаз в заголовке панели размывает логины и адреса в строках хостов,
панели действий и подробностях, редакторе, уведомлениях, предпросмотре скриптов,
импорта и экспорта, а также при проверке host key. Пока режим включён,
поля endpoint нельзя редактировать, а доверие новому host key нельзя
подтвердить до повторного показа адресов.

Это временный визуальный режим для демонстрации экрана, а не криптографическое
сокрытие. Он не меняет сохранённые профили и настоящий endpoint, копируемый из
панели, и не скрывает буфер обмена, внешние терминалы или адресоподобный текст
в произвольных названиях и заметках. Режим общий для экземпляров панели до
перезапуска процесса shell и не сохраняется на диск.

## Хранение и обновление

Профили и глобальные настройки находятся в:

```text
$XDG_DATA_HOME/vornashev.remote-hosts/
```

Путь по умолчанию — `~/.local/share/vornashev.remote-hosts/`. Каталог имеет права
0700, файлы данных и lock — 0600. Запись использует временный файл в том же
каталоге, `fsync` и атомарную замену.

При первом запуске версия 0.7 безопасно перемещает приватный каталог данных из
любого предыдущего namespace, если новый каталог ещё не существует. Небезопасные
права и symlink приводят к отказу. Пароль переносится из прежних атрибутов
application Secret Service при первом чтении, после чего найденная старая запись
удаляется.

Схема профилей остаётся версией 1:

```text
{version, groups, devices}
```

У хоста может быть необязательное логическое поле `pinned`; старые профили без
него загружаются без изменений. Неизвестные и секретные поля, повторяющиеся
JSON-ключи, некорректные связи групп и повтор endpoint отклоняются.

## Модель безопасности

- Пароли и парольные фразы ключей не попадают в argv, переменные окружения,
  JSON профилей, логи, буфер обмена и ответы helper. Не добавляйте секреты
  в скрипты.
- Секрет передаётся только через stdin/pipe минимального askpass. Askpass
  принимает исключительно точный запрос OpenSSH, привязанный к endpoint
  профиля, а для фразы — и к точному пути настроенного ключа.
- SSH использует фиксированные argv и `-F /dev/null`; local commands и forwarding
  отключены.
- Для входа по паролю и передачи сохранённой фразы обязателен
  `StrictHostKeyChecking=yes`; во втором случае также запрещены парольная и
  keyboard-interactive аутентификация.
- Новый host key требует просмотра SHA256 fingerprint и явного доверия.
- Конфликтующие, изменённые, revoked и certificate-authority записи не заменяются.
- Плагин не читает содержимое приватных ключей.
- Импортированные профили не заявляют наличие пароля или парольной фразы ключа.

`ssh-keyscan` не доказывает подлинность сервера. Сверяйте каждый fingerprint по
независимому доверенному каналу.

## Разработка

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest discover -s tests
omarchy plugin validate "$PWD"
scripts/qml-lint
```

Тесты используют синтетические endpoint, временные каталоги и поддельные внешние
программы. Они не подключаются к реальным хостам и не читают реальные credentials,
ключи, mount, профили или `known_hosts`.
